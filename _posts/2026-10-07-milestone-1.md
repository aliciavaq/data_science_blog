## Question 1

To download all NHL play-by-play data for the regular-season and playoff games from 2016-2017 season to 2023-2024 season, we used two functions.

<b> 1. get_season_game_ids(year) </b>

This first function retrieves the IDs of all regular-season and playoff games for a given NHL season. Each ID represents a unique identifier that can then be used to retrieve its play-by-play data from the NHL API.

The first step is to define the date range for the season. The <b> start_date </b> is September 1st of the given year and the <b> end_date </b> is October 31th of the following year. We chose this range because the NHL season generally begins in October and ends in June, including the playoffs. There was some exceptions, and the season 2019-2020 is a good example because the playoffs ended on September 28th, 2020. This date range therefore provides some extra time before and after the expected season. 

We initialize an empty set called <b> game_ids </b> to store the game IDs for the selected season. A set  only keeps unique values, which is useful because the NHL API returns schedules organized by game weeks, and since we advance through the calendar one week at a time, we want to make sure that we do not store the same ID twice.

We then initialize <b> current_date </b> with <b> start_date </b>, which determines the date used for the first API request. We use the NHL schedule-by-date endpoint (documented in the NHL API reference https://github.com/Zmalski/NHL-API-Reference#get-schedule-by-date) to retrieve the schedules associated with that date, using the URL <b> "https://api-web.nhle.com/v1/schedule/"f"{current_date.isoformat()}" </b>. The isoformat() method converts the date into the YYYY-MM-DD format required by the URL. 

The API response contains a <b> gameWeek </b> field, which groups games by week, so we can iterate though each week and then through each games listed for that week. For every game, we retrieve its ID and check 3 conditions : 1. "gameType" must be 2 (regular-season games) or 3 (playoff games) to exclude other game types. 2. The game ID must not be missing (for example, if there is no games during a week, we do not want to retrieve "empty" data). 3. The game ID must start with the starting year provided to the function to ensure that we do not get the data from the next or previous season (since the end_date is september 28th, it could be overlapping with the start of the next season). If all 3 conditions are met, the game ID is added to the set. 

After each request, we advance <b> current_date </b> by 7 days, and until <b> current_date <= end_date </b>. Once the <b> end_date </b> has been reached, the function returns the game IDs as a sorted list.

We also use print statements to display the season that we are retrieving the data from, and to display the number of games found.
<br>

<b> 2. get_hockey_data(year, path=None) </b>

Once we have the game IDs, the second function retrieves the play-by-play data for each game and combines the events into a pandas DataFrame.

The first step is to define the directory where the data will be stored. We can either provide a directory directly through the <b> path </b> argument or use the <b> HOCKEY_DATA_DIR </b> environment variable. If neither is provided, the function raises an error.

We then create a subfolder for the selected season, if it does not already exist, to organize the raw JSON files by season.

Next, the function checks if the optional <b> game_ids </b> has been provided. If it has not, the function calls <b> get_season_game_ids(year) </b> to retrieve all regular-season and playoff games IDs for the selected season. If a list of game IDS is provided, the function processes only those games. This is useful for the visualization steps, allowing us to retrieve data for specific games without downloading or processing the entire season again.

We create an empty list called <b> all_plays </b> to store the play-by-play DataFrames, then iterate through the selected game IDs or the IDs returned by the first function. For each game, we define the path of its JSON file using the game ID as the filename (example : a game with ID 2016010001 would be stored in a file named 2016010001.json).

Before making an API request, the function checks if the JSON file for that game already exists in the specified directory. If the file exists, its contents are loaded directly into Python to avoid downloading the same data again. If the file does not exist, the function downloads the play-by-play data from the NHL API using the URL <b> "https://api-web.nhle.com/v1/gamecenter/"f"{game_id}/play-by-play" </b>. We then convert the JSON response into a Python dictionary.

Before saving the data, we verify that the ID in the returned data matches the requested game iD and we check that the plays field exists and contains a list. After validating the response, we save the complete JSON data to the specified directory.

Next, we convert the game's events into a pandas DataFrame, and add a <b> game_id </b> column to identify the game associated with each event. This is important because the final dataset combines events from many different games.

Each game's DataFrame is appended to <b> all_plays </b>. Once all the game IDs have been processed, we concatenate the individual DataFrames into one large DataFrame. Each row represents an event and the columns contain the information associated with that event.

We also added a 1 second pause between each request with <b> time.sleep(1) </b> to reduce the frequency of API requests and avoid sending too many requests in a short period.

Additionally, print statements display a progress message after every 100 games and when the last game has been processed.

Since the second function can retrieve all game IDs itself when <b> game_ids </b> is not provided, we can call <b> get_hockey_data(year=2016) </b>, with 2016 as an example here, to retrieve the play-by-play data for an entire season. Alternatively, we can provide a specific list of game IDs to retrieve data only for those games.

### LLM + RAG-Assisted Data Acquisition

For the LLM part of task 1 we use RAG to search through NHL Web API documentation (Zmalski).It saves a snapshot of  the documentation, splits it  into chunks, embeds them with MiniLM, and indexes them in FAISS. It then it retrieves the top-k chunks by cosine similarity and saves them to `llm_docs/retrieved.md`. Those exerpts are then passed along with the user  prompt to Qwen3-4B-Instruct-2507 (FP16, Colab T4), which generates a function to fetch, cache and load a season’s play-by-play data.

### Generated Code
```python
[transformers] Both `max_new_tokens` (=1400) and `max_length`(=20) seem to have been set. `max_new_tokens` will take precedence. Please refer to the documentation for more information. (https://huggingface.co/docs/transformers/main/en/main_classes/text_generation)
import os
import pandas as pd
import requests
import time
from datetime import datetime, timedelta
import json
from typing import Optional

HOCKEY_DATA_DIR = os.getenv('HOCKEY_DATA_DIR')

def get_hockey_data(year: int, path: Optional[str] = None) -> pd.DataFrame:
    if path is None:
        path = HOCKEY_DATA_DIR
    if not path:
        raise ValueError("Neither path nor HOCKEY_DATA_DIR environment variable is set")
    
    season = f"{year}-{year+1}"
    season_dir = os.path.join(path, season)
    os.makedirs(season_dir, exist_ok=True)
    
    # Start date: September 1 of year
    start_date = datetime(year, 9, 1)
    # End date: October 31 of year + 1
    end_date = datetime(year + 1, 10, 31)
    
    game_ids = set()
    
    current_date = start_date
    while current_date <= end_date:
        date_str = current_date.strftime('%Y-%m-%d')
        url = f"https://api-web.nhle.com/v1/schedule/{date_str}"
        try:
            response = requests.get(url, timeout=30)
            response.raise_for_status()
            data = response.json()
            game_week = data.get('gameWeek', [])
            for day in game_week:
                for game in day.get('games', []):
                    game_id = game['id']
                    game_type = game['gameType']
                    if game_type in [2, 3] and str(game_id).startswith(str(year)):
                        game_ids.add(game_id)
        except requests.exceptions.RequestException as e:
            raise e
        current_date += timedelta(days=1)
        time.sleep(1)
    
    all_plays_data = []
    
    for game_id in game_ids:
        file_path = os.path.join(season_dir, f"{game_id}.json")
        
        if os.path.exists(file_path):
            with open(file_path, 'r', encoding='utf-8') as f:
                data = json.load(f)
        else:
            url = f"https://api-web.nhle.com/v1/gamecenter/{game_id}/play-by-play"
            try:
                response = requests.get(url, timeout=30)
                response.raise_for_status()
                data = response.json()
            except requests.exceptions.RequestException as e:
                raise e
            
            # Validate response
            if data.get('id') != game_id or not isinstance(data.get('plays'), list):
                raise ValueError(f"Invalid response for game_id {game_id}: id mismatch or plays not a list")
            
            # Save to file
            with open(file_path, 'w', encoding='utf-8') as f:
                json.dump(data, f, ensure_ascii=False)
        
        # Normalize plays and add game_id
        plays_df = pd.json_normalize(data['plays'])
        plays_df['game_id'] = game_id
        all_plays_data.append(plays_df)
    
    if not all_plays_data:
        return pd.DataFrame()
    
    return pd.concat(all_plays_data, ignore_index=True)
```

def load_season_games(year):

    season = f"{year}-{str(year + 1)[-2:]}"
    season_dir = DATA_DIR / season

    if not season_dir.exists():
        raise FileNotFoundError(
            f"The directory {season_dir} does not exist."
        )

    # Dictionary that stores the games 
    games = {}
    # Loop through all JSON files in the season folder
    for file_path in sorted(season_dir.glob("*.json")):

        with file_path.open("r", encoding="utf-8") as file:
            game_data = json.load(file)

        game_id = game_data.get("id")

        if game_id is None:
            game_id = int(file_path.stem)

        game_id = int(game_id)

        # 02 = regular season, 03 = playoffs
        game_type = str(game_id)[4:6]

        if game_type not in ("02", "03"):
            continue
            
        # Get list of the events from the game 
        plays = game_data.get("plays", [])

        if isinstance(plays, list):
            games[game_id] = {
                "game_id": game_id,
                "game_type": game_type,
                "plays": plays,
                "metadata": game_data
            }
    # Error if no games were found 
    if not games:
        raise ValueError(
            f"No games were found in {season_dir}."
        )

    return games

def update_games(change=None):

    global current_games
    
    # Load all the games from the selected season 
    try:
        current_games = load_season_games(
            season_widget.value
        )

        selected_type = type_widget.value

        matching_games = sorted([
            game_id
            for game_id, game in current_games.items()
            if game["game_type"] == selected_type
        ])
    
        if not matching_games:

            game_widget.options = []

            with output:
                clear_output(wait=True)
                print("No games are available for this game type.")

            return

        game_widget.options = [
            (str(game_id), game_id)
            for game_id in matching_games
        ]
        # atomatically selects the first game in the list 
        game_widget.value = matching_games[0]

    except Exception as error:

        with output:
            clear_output(wait=True)
            print("Error:", error)
# Update the event slider when a different game is selected

These visualizations are called interactive heatmaps, and they allow us to visualize the spatial repartition of shots by season and team. The colors in the heatmaps represent the difference between the team's shot rate in a given area and reference shot rate for that same area, measured per team-hour. Red indicates that the team took shots more frequently than the reference rate, while blue indicates a lower shot rate. White or very light colors indicate rates close to the reference.

If we look explore heatmaps from different seasons and teams, we can observe that shots are not uniformly distributed on the rink. Instead, they are concentrated in certain areas, particularly near the net. Comparing teams and seasons reveals differences in the areas where teams tend to take shots. However, these heatmaps only show the frequency and the location of shots, so they do not indicate scoring efficiency or the quality of the shots.


<b> Example 1 : Colorado </b>

In the 2016-17 season, the heatmap shows several blue areas and few red areas, suggesting that Colorado had a lower shot rates than the reference rates in several locations, especially the area near the net. This is consistent with the team's poor performance, as the Avalanche finished last in the NHL standings in that season. 

In contrast, the 2020-21 heatmap shows more orange/red areas across the rink, indicating that Colorado had a higher shot rates that the reference rates in several locations. This is consistent with the team's improved performance, since they finished first in their division (west).
